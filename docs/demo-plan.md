# Preliminary Under-Three-Minute Demo Plan

## Status

This is a **preliminary plan** for the final hackathon demo. The upload, processing, generation, B2, provenance, regeneration, and download moments described below are not implemented in the current foundation milestone.

Target runtime: **2 minutes 55 seconds**, leaving a small editing margin below three minutes.

## Demo outline

### 0:00–0:18 — Hook: the learner's backlog

**Visual:** A crowded watch-later list, PDFs, screenshots, notes, and two overlapping coding sheets; then the ZeroBacklog landing statement.

**Narration:** “This is not a lack of learning material. It is a decision problem. Every saved resource adds another choice, and the student still does not know what to do next.”

**Evidence:** Show the demo backlog's real count and estimated total time.

### 0:18–0:38 — Resource upload

**Visual:** Create an interview-preparation project and add the constrained mixed demo set.

**Narration:** “ZeroBacklog brings the backlog into one project without pretending every input is equally usable.”

**Evidence:** Show upload progress and real source objects being registered for B2 storage. Avoid pausing on form entry.

### 0:38–0:58 — Validation and transparency

**Visual:** Resource list settles into fully processed, partial, unreadable or unsupported states.

**Narration:** “Before analysis, each source is validated. One document is only partially readable, and one input is unsupported. Both stay visible and are excluded where necessary.”

**Evidence:** Open one state explanation and show what portion will influence the result.

### 0:58–1:23 — Knowledge reduction

**Visual:** A comparison view collapses repeated concepts, highlights a unique insight, flags one contradiction, and de-duplicates overlapping coding problems.

**Narration:** “The system compares knowledge, not just files. It preserves what is unique, surfaces conflicts, and turns repetition into a safe skip or skim decision.”

**Evidence:** Select a recommendation and reveal its source spans and confidence.

### 1:23–1:48 — Generated text, image, and voice assets

**Visual:** The learning path becomes concise notes, a useful visual map, and a short playable voice lesson.

**Narration:** “Genblaze orchestrates only the assets this learner needs. Each brief is tied to the selected evidence and each output has an evaluation state.”

**Evidence:** Play a very short audio excerpt, show the diagram's learning purpose, and point to evaluation badges.

### 1:48–2:08 — Selective regeneration

**Visual:** Mark the visual asset as unclear or show an evaluator warning; regenerate only that asset.

**Narration:** “A weak result does not restart the project. ZeroBacklog retries the smallest failed unit, preserves successful media, and records a new version.”

**Evidence:** Other asset timestamps remain unchanged; the visual moves from version 1 to version 2.

### 2:08–2:30 — B2 storage and provenance

**Visual:** Compact provenance panel plus a brief B2 object view containing original, generated assets, evaluation/manifest data, and the new visual version.

**Narration:** “Backblaze B2 is the durable artifact layer. Originals, derivatives, evaluations, and versions remain connected, so the learner can trust where the pack came from.”

**Evidence:** Show non-sensitive object identifiers, source/derivative relationship, checksum or version, and approved state. Never reveal credentials or private URLs.

### 2:30–2:46 — Final downloadable Action Pack

**Visual:** The final path shows the first action and reduced resource count. Download the manifest-backed Action Pack and briefly reveal its approved contents.

**Narration:** “The learner leaves with a smaller path, multiple ways to revise, and one clear next action—not another folder of summaries.”

**Evidence:** Download succeeds through the controlled B2-backed flow.

### 2:46–2:55 — Closing impact

**Visual:** Before/after: the original backlog beside the next-action card.

**Narration:** “ZeroBacklog turns saving for later into learning now. Stop Saving. Start Learning.”

## Recording requirements

- Use a stable, pre-validated demo dataset with permission to display its content.
- Keep one planned imperfection in the dataset to demonstrate transparency.
- Pre-warm nonessential cold starts while preserving authentic processing evidence.
- Use measured numbers from the demo run, not the illustrative landing-page preview.
- Capture a fallback recording of provider-dependent stages.
- Hide browser bookmarks, local paths, account identifiers, provider keys, bucket credentials, and private endpoints.
- Keep the B2 proof concise and legible; object storage should support the story rather than become a console tour.
- Add captions for narration and text equivalents for meaningful audio/visual output.
- Rehearse to 2:45–2:50 so transitions do not exceed the hard limit.

## Demo acceptance checklist

- [ ] Hook shows a recognizable learner problem.
- [ ] Upload uses a mixed but intentionally constrained resource set.
- [ ] At least one non-success transparency state is visible.
- [ ] Reduction includes repetition, uniqueness, contradiction, and coding overlap.
- [ ] A recommendation displays evidence and confidence.
- [ ] Genblaze produces useful text, image, and voice outputs.
- [ ] Evaluation state is visible.
- [ ] One asset regenerates without rerunning the rest.
- [ ] B2 shows originals, derivatives, provenance, and versions.
- [ ] The final approved Action Pack downloads successfully.
- [ ] Closing shows a defensible before/after outcome.
